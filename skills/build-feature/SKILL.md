# Build a feature — the spec-kit cycle with no human gate

**Premise, shared with every skill in this set:** the code is written by LLM agents and no human reads it line by line. The consequence for a feature is that the human gates spec-kit puts between its commands — *review the spec before planning*, *review the plan before tasks* — are the last place a person reads anything, and on 2026-09-16 both of them found blocking defects only because the reviewer was a fresh context, not a person. This skill keeps the fresh context and drops the person: one deterministic script, one subagent per stage, a refutation review where each gate was, and a converge loop that ends at a severity floor, which by default tolerates no finding at all — because on the one run that tested it (2026-09-18) converge had no fixed point, and the owner's decision the same day is that a tolerated finding is a finding left open.

## Run the workflow; orchestrate nothing yourself

**Call the Workflow tool with this skill's script and the two inputs the user supplies, and run no spec-kit command from your own context.**

```
Workflow({
  scriptPath: "${CLAUDE_SKILL_DIR}/workflow.mjs",
  args: {
    source: "Create a feature spec from <path to the upstream spec, or the description>",
    shortName: "<spec-kit short name, e.g. product-version>"
  }
})
```

The path above is this skill's own directory, substituted by Claude Code when the skill loads; the script is not a named workflow and lives nowhere else. A workflow starts only from a script the session may read, so a skill installed outside the working directory (a user-level install under `~/.claude/skills/`) needs that directory added first — `/add-dir` with the same path, or a `Read` allow rule — where a project-level install under `.claude/skills/` needs nothing. From a terminal, with no session open, the same run is `claude -p "/build-feature <source> shortName=<name>" --permission-mode bypassPermissions`; the session that dispatches can be the cheapest model, since it does nothing but this one call, and it stays open until the workflow ends (the idle ceiling is `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`).

Optional `args`, all with a default: `baseBranch` (preflight refuses to start on any other branch), `wall` (the definition-of-done command; when absent, preflight reads it from the project's `CLAUDE.md`, which names it), `planGuidance` and `tasksGuidance` (passed to `/speckit-plan` and `/speckit-tasks`), `push` (default true), `mergeInto` (fast-forward that branch when converged; default none), `maxReviewRounds` 3, `maxAnalyzeRounds` 3 (both were 2 until 2026-09-18; the 2026-09-17 record is five launches out of seven ending at one of these caps and the operator resolving each with one more fix round, which is the loop declining work it could do), `maxConvergeRounds` 6, `maxWallAttempts` 3, `severityFloor` (the highest converge severity the loop tolerates; default `NONE`, which tolerates none), and `tiers` (below). To restart a feature that already has artifacts, pass `featureDir`, `branch`, `wall` and `from` (one of `preflight`, `specify`, `clarify`, `review-spec`, `plan`, `review-plan`, `tasks`, `analyze`, `implement`, `converge`, `finish`); `until` bounds a run the same way. `wall` is required on a restart because preflight is the stage that reads it from `CLAUDE.md`, and a restart skips preflight; the script refuses to start without it. A run that was interrupted resumes with `resumeFromRunId`, which replays every finished agent from its journal.

The default an agent reaches for is to run `/speckit-specify` itself, read the result, decide it is fine, and continue — the human gate moved into the orchestrator's own context, where the reviewer that approves the spec is the context that wrote it. Rejected, 2026-09-16: two fresh-context reviews found a constitution lagging the plan, a test-property precedence error and an ArchUnit scope error that the writing context had approved. The previous entry point, `specify workflow run speckit`, is rejected too: its gates read a terminal and pause without one, its `model` is per step but effort is not (the Claude integration rejects per-step `integration_args`; the only extra-flag path is one process-wide environment variable), and its command steps capture no output, so nothing in it can loop on what converge reports.

## Each stage runs on the tier it earns

**Take the model and effort of every stage from the `TIERS` table in `workflow.mjs`, and take every row from the roster of six: Haiku, Sonnet 5 low, Sonnet 5 medium, Opus 5 low, Opus 5 medium, Fable 5.1 low. Change a row for one run with `args.tiers`, never by editing the table.** The aliases resolve to the newest model of each line. No other pair exists for this script: a row on `high`, `xhigh` or `max`, or on Fable above low, fails the run before its first agent starts, whether it came from the table or from `args.tiers`.

| Stage | Tier | Why this tier |
|---|---|---|
| preflight, phases, finish | Sonnet low | shell commands and parsing; the return value is a list of facts |
| handoff | Sonnet low | writes one file whose whole text the script hands it, commits it, pushes it; nothing in the stage is a judgment |
| specify, clarify, fix-spec | Opus medium | transcribes a written source into the template and records decisions; the review behind it catches what it misses |
| review-spec, review-plan | Fable low | the refutation that stands in for the human; the roster's tier for an adversarial review, at the one effort the roster admits it on |
| plan | Fable low | the one decision-heavy pass; every later stage inherits its errors |
| fix-plan, remediate (critical) | Opus medium | edits that may reach the constitution |
| tasks, analyze, remediate | Opus medium | decomposition and cross-checking of artifacts a stronger tier already reviewed |
| implement, one agent per phase | Opus medium | a bounded context per phase; the wall is the check, and effort here buys fewer red-wall retries |
| converge | Opus medium | reads the whole implementation, up to six rounds and one assess-only round after them, grades every gap it finds on `/speckit-converge`'s own Step 5 scale, and what it appends is implemented and then wall-checked; the row to raise with `args.tiers` when a converge misses a gap a person can see, or grades one below a raised floor |
| reconcile-tasks | Opus medium | reads `tasks.md` against git after a failed forced append and brings it to a known state; git makes the evidence deterministic, but a wrong deletion here removes real tasks and the row must return `unsure` rather than guess, which is the calibration the cheap tiers are worst at — and its verdict is certified by the parse-only `phases` row, not taken on its own word |
| force-append | Opus medium | authors one task per finding a converge round graded and declined to append, each stating both closure routes, and judges per finding which route the task leads with; not a clerical row like `handoff` — the script hands it findings, not a finished document, and a paraphrase here becomes a task that closes on something else |

Three roster tiers go unused. Haiku, because no stage is locate-and-quote: preflight, phases and finish each parse and refuse, handoff writes and commits, and force-append writes task text it has to think about. Sonnet medium and Opus low, because every writing stage is priced at Opus medium and reviewed by a stronger tier, and lowering one is a measurement this skill has not taken. The default is one model for the whole run — the session's. Rejected because the run is dominated by reading and shell output, where the tier changes the price and not the result, while the three stages that decide (plan and the two artifact reviews) are the whole of the quality. Fable at high and xhigh effort on those three stages was also rejected, 2026-09-17: two runs spent 1.19M and 0.91M subagent tokens without leaving review-spec. The roster admits Fable at low effort only; whether low effort brings that spend down is the next run's measurement, not a claim here.

(Check: `tier()` in `workflow.mjs` refuses any row whose model and effort are not a roster pair, from the table or from `args.tiers`, before the first agent starts, and the run's progress tree labels every agent `<stage> (<model> <effort>)` — *bespoke*, `workflow.mjs`, 2026-09-18.)

## A gate is a fresh-context refutation, not a human

**Where spec-kit pauses for approval, a review agent with no memory of the writing is prompted to refute the artifact and returns findings as data; a fix agent applies them; the review runs again; blocking findings still open at the round cap end the run as `needs-human` with the findings attached.** Review-spec reads the upstream source, the spec and the constitution and reports every source requirement without a counterpart, every contradiction, every invented requirement, every untestable one and every leftover marker. Review-plan reads the spec, every plan artifact, the constitution, the project rules and the code the plan touches, and reports every requirement no design element realises, every gate or article the design violates, and every contract that contradicts the schema. A verdict of approve with only minor findings applies the minors once and does not re-review. The cap is 3 fix rounds and 4 reviews, and the exit's reason says so — a `needs-human` `why` states what the loop attempted and how often, because the point of the handoff is to tell *nobody tried* from *tried three times and failed*. A constitution amendment is proposed or applied only when it passes the constitution's own admission test — the rule binds two or more features, or a table the feature does not own; a rule about the feature's own tables is a plan decision and the finding is against the plan. Rejected, 2026-09-17: without the test, two plans grew Article VII from three sub-articles to fourteen, most of them one feature's schema written as law, and the third feature's spec had to start by amending three of them.

(Check: the workflow's return value is `status: "done"` only when every review and analyze loop's last verdict was clean and, where the run reaches finish, the finish wall is green — a run whose `until` stops before finish returns `done` with `finish: null`, having run no wall of its own; otherwise it is `status: "needs-human"` with the stage and the findings. Those two are the script's only *returns*: a bad argument, a tier outside the roster or a stage that returns nothing throws instead, which is a failed run and neither of them. The converge round cap is not a return of its own — it is `converge.ended: "round-cap"` on a `done` return — *bespoke*, `workflow.mjs`, 2026-09-18.)

## Analyze goes back to the artifact it names; converge goes back to implement

**A finding is resolved by editing, in place, the artifact it names — never by re-running the command that generated that artifact.** `/speckit-analyze` finds coverage gaps, contradictions and constitution violations across spec, plan and tasks; the remediation agent adds tasks with new ids for a coverage gap, changes the plan or the spec for a violation, and touches the constitution only when the finding says the constitution is what is wrong; then analyze runs again. `/speckit-converge` appends one phase of tasks and returns every gap it found — appended or not, actionable or not — graded by that skill's own Step 5 severity rule, whose four values `CRITICAL`, `HIGH`, `MEDIUM` and `LOW` are the same four the analyze schema carries, so no second vocabulary enters the run; the next implement agent runs that phase alone; converge runs again. **The severity floor is the loop's only stop test: the loop ends on the first round whose findings hold nothing above the floor, and the return value says whether that round had appended tasks (`severity-floor`) or nothing (`converged`). The floor is `args.severityFloor`, and it is `NONE` by default — `NONE` ranks below every graded severity, so every finding the assessment grades is above it and the loop tolerates nothing. The legal values are `NONE`, `LOW`, `MEDIUM`, `HIGH`; a run raises the floor to `LOW` or `MEDIUM` when it wants the loop to stop at the gaps a person would notice, and that is the one setting that changes when the loop stops. `CRITICAL` is refused rather than offered: `/speckit-converge` Step 5 grades a constitution MUST violation there, so a floor at `CRITICAL` tolerates every finding the scale has and ends the loop after one round.** Under `NONE` the exits mean this. `converged` is the only clean stop and requires a round that appended nothing *and* graded nothing. **A round that reports converged while still grading a finding above the floor is not a human question: the loop appends those findings itself, as a forced convergence round, and implements them.** `/speckit-converge` Step 7 calls a round converged on *no **actionable** findings* and Step 4 surfaces gaps for awareness, so a graded finding on a `converged` return is that skill judging a gap non-actionable — which is the judgment the floor exists to decline. A floor that declines it owes the work it withheld, so one `force-append` agent receives the findings the script filtered, rendered by the script and never paraphrased, appends one task per finding as `## Phase N: Convergence (forced round n)` in `/speckit-converge`'s own append format, commits `tasks: forced convergence round n`, and the appended phase goes through the same implement agent and the same wall gate as any other. **Each forced task is closable two ways, and its own text says both: fix the defect, or record in `<featureDir>/convergence-rationale.md` why it is not a defect.** Not every finding is a code change — a requirement about an *absence* ("this capability contains no approval gate") has no code to cite, and a task demanding a citation invites a fabricated one, which is worse than the open finding; the force-append agent leads such a task with the rationale route and returns which route each task leads with. The rationale closes the task only once it is written in the file: a claim in an implementer's summary or commit message does not. **A finding is forced at most once.** Identity is its severity, location and summary, normalised; the set forced in the run is tracked across rounds and returned as `converge.forced`. A forced round is done inside the slot of the round that discovered it and the loop then re-assesses, exactly as after an appended round, so `maxConvergeRounds` remains the single bound on the stage. **A finding that comes back above the floor after its forced round is the `needs-human` exit, and the handoff says the loop already tried** — appended a task against it, implemented it with the wall green, and the assessment reports it again. That distinction is the value of the handoff: a person reading it knows the difference between nobody having tried and the loop having tried and failed. A red wall after a forced phase and a forced task left unchecked are `needs-human` after the bounded repair and second pass every phase gets; a forced append that cannot write `tasks.md` is reconciled and retried once first (below). Rejected, 2026-09-18: escalating a `converged`-with-findings round straight to a person, which is what this skill did until that date. Ground — feature `specs/002-product` stopped on four LOW findings under floor `NONE` (FR traceability citations, one `GATES.md` table row described too thinly, two test and naming wordings), every one of them a mechanical edit, and the handoff asked a person to do exactly what the loop's own agents could: decide whether it is real, and either apply the fix or record why it is not a defect. A round that appends tasks and grades nothing has shown nothing, counts as above the floor, and the loop goes on. The in-loop `severity-floor` exit is unreachable under `NONE` and belongs to a run that raised the floor. **So `maxConvergeRounds` — still 6 — and not the floor is what ends a long run on a real feature, and a caller who wants more passes raises the cap rather than the floor.** The cap is followed by one assess-only round that appends and commits nothing, because every round before it implemented what it found and its findings are therefore closed work; that final assessment's findings are the ones the run carries, under `"round-cap"` — open and unimplemented — when it grades anything above the floor, and otherwise under `converge.ended: "severity-floor"`, or `"converged"` when the floor is `NONE`, since a label naming a floor that tolerates nothing would say the wrong thing about a round that found nothing. A `round-cap` goes to finish, where the wall decides: it is a reported outcome, not a human question. A red wall after an appended or forced phase, or its task left unchecked, is `needs-human` after the bounded repair and second pass every phase gets (below). The default an agent reaches for — loop until converge appends nothing — is rejected, 2026-09-18: on `001-product-hierarchy` converge had no fixed point, took five passes, and the fifth appended nothing only because the operator had stopped applying findings below the floor. A `LOW` default floor is rejected too, and it is the one this skill shipped for part of 2026-09-18 on exactly that evidence: **the owner reversed it the same day, on the ground that a tolerated finding is a finding left open, having been shown the no-fixed-point run and reaffirmed.** The cost is real and accepted: under `NONE` a run will usually end at the round cap or at `needs-human` rather than at a clean converge, and the wall plus the reported findings, not an empty finding list, are what say the feature is done. Re-running specify, plan or tasks is rejected because each regenerates its file whole and discards every review fix that came before.

(Check: the feature branch's `git log` carries `spec: review round N`, `plan: review round N`, `tasks: analysis round N`, `tasks: convergence round N` and `tasks: forced convergence round N` commits and a second `/speckit-plan` run appears nowhere — *convention*, 2026-09-17. The converge stage's return carries `findings[].severity` on the four values of `/speckit-converge`'s own Step 5 scale, the loop compares each against the floor by rank rather than by equality with `NONE` ranking below every graded severity, a `severityFloor` that is not one of `HIGH`, `MEDIUM`, `LOW`, `NONE` throws before the first agent starts, `CRITICAL` with a message saying why it is not a floor, the floor never appears in the converge prompt so it cannot move a grade, and the run's return carries `converge.ended` as one of `converged`, `severity-floor`, `round-cap` with `converge.floor` and the findings of the assessment that ended the loop — on a run at the default floor `severity-floor` never appears — *bespoke*, `workflow.mjs`, 2026-09-18. A `converged` round carrying a finding above the floor dispatches one `force-append` agent whose prompt holds the findings rendered by the script and no mention of the floor, the run's return carries `converge.forced` as one entry per finding the loop appended itself with the round that did it, and no identity appears in it twice — *bespoke*, `workflow.mjs`, 2026-09-18.)

## Unattended means the agent decides by a written rule

**Every question a speckit skill would put to a person is answered by the rule in that stage's prompt, and the answer is written into the artifact.** Specify resolves each `[NEEDS CLARIFICATION]` from the source, otherwise takes the most conservative option and records it under `## Assumptions`. Clarify plays both roles: it generates its question queue and answers each in this order of authority — what the source states, what the constitution requires, what the code already does, else the skill's own recommendation — and records every pair under `## Clarifications`. Implement proceeds past an unchecked checklist and lists the items. Analyze returns findings instead of offering remediation. A stage that has to ask stops the run: that is the `needs-human` exit, and it is the only one. **And a run never hands back work it could have done itself: every escalation is either something the loop attempted and failed at, or something it is not authorised to do** (owner's rule, 2026-09-18). So a red wall gets one fresh-context repair pass before it escalates — the implementing agent had already run the wall `maxWallAttempts` times inside its own context, so what is missing is a second context reading the same failure, which is this skill's premise for every review gate — and a phase with tasks left unchecked gets one second pass over exactly those ids, the shape the implement stage already had and the convergence phases did not. Three implement agents per phase is the ceiling; there is no third shape and no retry of a retry. A red wall at `finish` is repaired the same way, and **the re-check is a second `finish` agent rather than the repairing agent's own word: an agent that repairs a gate is not the one that may declare it green.** **No gate is ever weakened to make a wall pass.** The repair prompts enumerate what is forbidden — skipping, disabling, quarantining or deleting a test; a suppression, exclusion, baseline entry, waiver or ignore comment; a lowered threshold or coverage figure; a relaxed or removed gate; an edit to the wall script, the build file or any gate configuration; a force flag — and tell the agent that where the only route it can see is one of those, it changes nothing, leaves the tree as it found it and returns the wall red. A green wall bought that way is strictly worse than the escalation it would replace, and it is the one outcome this run cannot accept. **A failed forced append is reconciled rather than escalated.** When the `force-append` agent reports it could not write `tasks.md`, one reconcile agent reads that file against git — at that instant nothing else in the run has touched it since the previous round's work was committed, so an uncommitted change to it is that agent's own partial write and `git checkout` restores the committed file exactly — and brings it to one of two known states, wholly absent or wholly present, with nothing partial surviving. The parse-only `phases` reader then certifies that state independently, because the agent that cleans up is not the one that certifies the result. Wholly present means the phase was written and the agent failed only to say so, and the loop implements it rather than appending it twice; wholly absent means one retry of the append. The reconcile may write to `tasks.md` and nothing else, never ticks or unticks a task, never touches a phase other than this round's forced one, and returns `unsure` rather than a guess. Rejected, 2026-09-19: escalating a failed append on the spot, which this skill did for one day. The ground is the owner's rule again — *somebody needs to look at `tasks.md`* is not a human-only act — and the corruption risk that reasoning rested on is real but is an argument against a **blind** retry, which is not what this is.

**What still escalates: eight reasons, across thirteen exits.** (1) A repository preflight refuses on — a dirty tree, the wrong branch, a missing speckit skill, a source path that does not resolve — because acting means committing or discarding somebody's uncommitted work, switching branches or installing a skill. (2) No definition-of-done command, because inventing one is guessing the owner's intent. (3) A review or analyze cap with findings still open after three fix rounds and four reviews. (4) A wall still red after its one fresh-context repair pass, at a phase or at finish. (5) A task two implement passes decline to tick. (6) A converge finding that survives its own forced round. (7) A reconcile that cannot establish what is in `tasks.md`, or a reconcile and a parse-only reader that disagree about it — acting on either account deletes real tasks or leaves a duplicate phase, and neither is recoverable. (8) A forced append whose reconciled retry failed as well. Every one of them carries what was attempted and how often, and (7) and (8) carry the reconcile's quoted evidence, so nobody is sent to work out the state of a file the run has already read. A converge loop that runs out of rounds is not asking — it is reported and the run goes on to the wall, and at the default floor that is the ordinary end of a long run rather than an exception. Neither is a converge round that grades a gap and declines to append it: the loop appends that work itself and implements it, and only a finding that survives its own forced round becomes a question.

(Check: a `[NEEDS CLARIFICATION]` or template placeholder left in any artifact is a blocking finding of the next review, so it cannot survive to implement — *bespoke*, the review prompts in `workflow.mjs`.)

## A needs-human exit leaves a file behind

**Every `needs-human` exit writes `HANDOFF.md` into the feature directory, commits it on the feature branch, and pushes it when `push` is true, before it returns.** The file is the handoff surface: it says at the top that the run stopped and what decision is being asked, and then carries the stage it stopped at, the reason, the full findings rendered item by item, the branch, the round counts, the stages that ran, the definition-of-done command, the severity floor, the run's date, the arguments that restart the run at that stage, and the path of the run journal for whoever has the machine. It is written by one Sonnet-low agent, because the script runs in a sandbox with no filesystem and no `Date`; the document itself is rendered in `workflow.mjs` and handed to that agent finished, with two placeholders — the date and the journal path — so the cheapest tier in the table cannot paraphrase a finding or drop one. The commit is by pathspec, that one file and nothing else, because the tree at a `needs-human` exit may hold the run's failing work. The gap this closes was observed 2026-09-18 on run `wf_7e4e8726-4b5`: a converge exit's three findings existed in the invoking session's tool result, a file under `/tmp` and the machine-local run journal — three places, none of them the repository, and a colleague could reach none of them.

**A failed handoff never costs the run its verdict.** A handoff agent that throws, is skipped or returns nothing leaves the full `needs-human` payload — stage, reason, findings and all — on the return value exactly as before, with `handoff.written: false` and the reason in `handoff.note`; losing the findings because a write failed is strictly worse than not writing. **An exit before a feature directory exists writes nothing and says so there instead.** That is every preflight exit, and it is deliberate: there is no feature branch to carry the file, a preflight refusal is a repo-state fact the next person reproduces in one command rather than a finding that exists nowhere else, and a dirty tree is one of the states preflight refuses on — so a commit at the repo root would sweep somebody's uncommitted work into a handoff commit. The red wall at `finish` is the thirteenth exit and gets the same file, on a return that keeps its own shape with `handoff` added.

(Check: `needsHuman()` is `async`, every one of its twelve call sites is `return await needsHuman(...)`, the finish red-wall return awaits `writeHandoff` too, the whole dispatch sits in a `try` whose every failure path returns a `written: false` record rather than throwing, and the push instruction appears in the handoff prompt only when `args.push` is true — *bespoke*, `workflow.mjs`, 2026-09-18. On a run that stopped, the feature branch's `git log` carries a `handoff: the <stage> stage stopped and needs a person` commit touching one file — *convention*, 2026-09-18.)

## What this skill does not do

It does not read the handoff file back: a run that restarts does not know one was written, and nothing reconciles `HANDOFF.md` with the state of the feature — the file is a report for a person, and a stale one is stale until the next exit overwrites it. It does not install spec-kit or its skills; preflight fails when `speckit-specify` through `speckit-converge` are missing under `.claude/skills/`. It does not choose the definition of done: the project's `CLAUDE.md` names the command, or `args.wall` does. It does not merge unless `mergeInto` says where, and it never opens a pull request. It runs its stages in sequence — a feature's artifacts are one dependency chain and nothing in it is independent enough to fan out. It is Claude Code only: the Workflow tool, the skill-directory substitution and the per-agent model and effort are that client's, and the portable part — the stage prompts and the loop — is readable in `workflow.mjs` for anyone porting it. It has no measured cost yet: the one run it is modelled on took a working night with a person at the gates, and the tier table is a decision, not a measurement. It removes the one gate the rest of this set assumes a person reads — the plan, the last cheap moment a wrong decision is caught — and puts the review-plan refutation there instead; a person who wants that read runs with `until: "review-plan"`, reads the plan, and continues with `from: "tasks"` and the same `featureDir`.

**Status: *decided, not yet validated*** — written 2026-09-17 from one hand-driven run of spec-kit's own workflow; one feature built by this script end to end since (2026-09-17), and the severity floor added 2026-09-18 from a hand-driven converge run, corrected the same day by an adversarial review of the commit that added it and then defaulted to `NONE` by the owner's reversal later that day, has not yet been run by the script at any floor. **The forced convergence round and the bounded wall repairs (2026-09-18), and the reconcile-then-retry behind a failed forced append (2026-09-19), are unvalidated in the same way and more narrowly: no run has taken any of them** — they were driven against a stub of the sandbox over twenty-two shapes, which is a reading of the script and not a run —, and the run whose handoff prompted it — `specs/002-product` on four LOW findings — is evidence that the escalation it replaces was wrong, not evidence that the replacement works. To run the converge loop alone against an implemented feature, the entry point is `converge-feature`, which calls this script. **Firing:** meant to be invoked by name (`/build-feature`); whether the description earns the load on "build this feature from the spec" is unmeasured.
