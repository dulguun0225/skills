# New Rust backend — from an empty directory to the template's init commit

**Premise, shared with every skill in this set:** the code is written by LLM agents and no human reads it line by line. The consequence for the first session of a project is specific: **scaffolding is not a decision, so nothing an agent writes during it is wanted.** The stack — Rust stable at an exact pin, edition 2024, tokio, axum 0.8 with tower-http, utoipa, sqlx 0.9 with checked macros only, PostgreSQL 18 — was chosen on 2026-09-28 by `backend-stack`'s criterion in the [Rust stack record](https://github.com/dulguun0225/skills/blob/master/docs/history/rust-backend-stack.md). The template `dulguun0225/rust-backend-template` is that record's gate list wired, each gate shown failing by a canary or a negative fixture, and green, after an adversarial review on 2026-09-29 whose fixes are in the pinned commit, as are the trivy scan of the service image and the checksum pin of every tool mise installs (`mise.lock`), both wired the same day. This skill is the procedure that lands it, and it ends at the script's `init:` commit.

**No Rust rules skill exists yet** (2026-09-29): nothing here is the Rust counterpart of `java-backend-rules`, `java-backend-api` or `java-backend-observability`. The rules a Rust service is held to are the stack record and the template's [`docs/GATES.md`](https://github.com/dulguun0225/rust-backend-template/blob/main/docs/GATES.md), which lands as `backend/docs/GATES.md` (at the root with `--standalone`). It maps each gate to the record section or the published directive it implements — among them `money`, `money-storage`, `primary-keys`, and the language-neutral content of the Java-named skills, with the Rust form in the row — and lists what no gate reaches.

## Run the script; write nothing

**Run [`scripts/new-backend.mjs`](scripts/new-backend.mjs) from this skill's own directory, with the one input the user supplies, and write no file yourself.** The input is the service name, the only thing about a scaffold that is the project's to decide: it names the binary, the OpenAPI document's title, the image and the local database. It is a lowercase letter, then lowercase letters, digits or underscores, 64 characters at most, and the template's `init.mjs` also refuses a Rust keyword and a name Cargo uses. Ask for it rather than inventing it: the rename is permanent once the tree exists.

```
node <this skill dir>/scripts/new-backend.mjs --name <name> --dir .
```

The default is vendored: the directory is the project root, the template lands in `backend/` by `git subtree add` at the pinned commit, and its own `init.mjs` renames and lifts the project-level files one level up — root CI with `backend` and `frontend` jobs for GitHub and GitLab, the branch rulesets, `compose.yaml`, the `frontend/` stub, the project `CLAUDE.md`. Then `cargo fmt --all`, `mise install` and the template's wall, `node scripts/wall.mjs`, through `mise exec`; the wall is the template's definition of done and starts its own throwaway PostgreSQL container. The result is committed as `init: <name> from rust-backend-template <sha> (wall green)`. `--standalone` is for a repository that *is* the service; `--skip-verify` defers the formatter and the wall, and the commit message says so. The script checks its own preconditions before it creates anything: the directory is empty or absent, `git` is on `PATH`, and verification needs `cargo` from rustup, which reads the template's `rust-toolchain.toml`, `mise`, and a running Docker. A name the template's `init.mjs` refuses leaves nothing behind.

The default an agent reaches for — a workspace `Cargo.toml` with its lint table, a `clippy.toml` ban list, a `deny.toml` and a CI file, written from memory or from the stack record — is rejected on three grounds. It costs the first session. It produces a different ban list each time. And on this stack a hand-written lint configuration passes while enforcing nothing, in ways the record ran on clippy 1.98.1 on 2026-09-28: a misspelled path under `disallowed-methods` is a warning and exits 0 even under `-D warnings`; `--cap-lints allow` or `warn`, on the command line or in `RUSTFLAGS`, makes a `forbid` violation exit 0; a workspace member without `[lints] workspace = true` inherits no lint and passes clippy; a crate-local `clippy.toml` replaces the root file rather than merging with it. The template's runs of 2026-09-29 found more that a list written from the record would get wrong: `expect_used` at `forbid` fails with E0453 on `#[tokio::main]`, confining anyhow takes four ban entries, and a ban path whose crate is not a dependency is ignored with no warning. The adversarial review the same day found about fifteen routes that built banned code while every check stayed green, among them `#![warn(warnings)]`, code under a `cfg` clippy never compiles, `#[path]` and `include!`, a path dependency outside the workspace, renamed lint names, and profile, `CARGO_*`, `--config` and `.cargo` overrides of the overflow and panic settings. The template's configuration is the one those runs left green, held by a marked canary per ban entry that fails the wall when missing, `scripts/check-lint-config.mjs` and the wall's clippy step, which between them refuse those routes, and `scripts/clippy-scopes.mjs`, and it is one tree for a given commit and name.

**A service works on `dev`, never on `main`.** `dev` is the branch the script's `git init -b dev` makes, and the project `CLAUDE.md` states it in one line, `` Base branch: `dev` ``. The script also makes `main` at the same commit, and the printed steps push both and make `dev` the forge's default branch. Everyone commits to `dev` directly — its ruleset forbids only deletion and a force-push. `main` takes pull requests from `dev` only, by merge commit, when `dev` is stable: the lifted `.github/rulesets/main.json` forbids a push to it, and the `backend` CI job fails a pull request into it from any other branch. Tools that read the `Base branch:` line read it from the root `CLAUDE.md` only, so the vendored `backend/CLAUDE.md`'s line is not the project's.

The pinned commit is `DEFAULT_REF` inside the script. It moves deliberately, in a commit that says which gate change it brings in; `--ref` overrides it for one run, and `TEMPLATE_URL` in the environment points the script at another copy of the template.

(Check: after the run, the directory's `git log` holds the script's `init:` commit and nothing hand-written precedes it; a build file that exists before that commit is the finding — *convention*, 2026-09-29.)

## Stop where the script stops

**Do only the printed next step that has no side effect outside the directory, and hand the rest to the user by name.** The script stops, on purpose, before anything that touches the forge or the wider machine, and prints those steps: `gh repo create`, `gh repo edit --default-branch dev`, in a vendored project `node scripts/apply-ruleset.mjs`, and `npx skills add dulguun0225/skills -g -a claude-code -y`; after `--skip-verify` it also prints the formatter and wall command to run before the first push. Skip `npx skills add` when this skill is already installed, which it is if you are reading this. Do not create the forge repository or apply the rulesets unless the user has named the organisation and asked for it in this session.

The skill ends at the script's `init:` commit. The closing report says what was run, what failed, and which forge steps were left to the user, and stops there.

(Check: the session's tool calls contain no `gh repo create` and no `apply-ruleset` the user did not ask for by name — *convention*, 2026-09-29.)

## What this skill does not do

It does not choose the stack — the record did, by `backend-stack`'s criterion. It does not state or explain a rule; no Rust rules skill does yet, and until one exists the template's `docs/GATES.md` and the record are where a rule is read. It does not verify that the template's pins were newest at their recorded date, 2026-09-29; the template records each pin with its source and date, which is a convention performed once that decays. It does not reach what the template's gap table names — among them feature isolation inside one crate, OpenTelemetry export, an SBOM with osv-scanner, the licences of the image's packages, a checksum for sqlx-cli, which is built from source, the nightly-only tools, an outbox, and authentication. It has not been run on Windows or macOS: the script is Node on the standard library, and the claim that it runs there is the standard library's until someone runs it.
