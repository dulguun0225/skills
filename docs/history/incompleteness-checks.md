Doing one of these is a bounded session, not a research project. The layer check
is a read of the file asking one question per directive; the composite-shape
check is a list written before anything is verified. Neither needs a panel, and
**neither may promote a marker** — a check that finds nothing changes no
confidence marker, because finding nothing is not verification. What it may do
is add directives, and those then arrive at the normal bar.

**First evidence about what these checks are worth, 2026-08-02.** The layer,
predicate and composite-shape checks were run over `primary-keys` in one session,
exactly as the paragraph above priced them. Four things learned, and they apply to
every row still marked *owed*:

- **The layer check's yield was not a missing rule; it was a stated gap that was
  false.** The skill's own named-gaps list claimed coverage its only named host
  could not deliver. **A gap list is text like any other and can be wrong in the
  direction that flatters the file** — so read the gap entries against the check
  lines beside them, not only the directives.
- **The remedy was already published in a neighbouring skill and had not been
  carried across.** `money-storage` `M-35` splits the same enforcement problem into
  an architecture predicate plus a lint over committed query text. Running the layer
  check well means asking which sibling already solved the two-language problem for
  its own values, not inventing a host.
- **Running a check obliges the same sweep a publish does.** It touched
  `java-backend-rules`, `java-backend-observability`, `README.md`, both
  `primary-keys` files and this page. **The edit that mattered most was in a file the
  check was not run against** — a sibling sentence describing the ban as hostable by
  one test class.
- **Two of this table's *owed* rows stated grounds that were false about the file
  they described** — `caching`'s and `async-handoff`'s layer-check cells both named
  crossings the directives already named. **The rows were written from memory of
  those skills rather than from a read of them**, which is the same defect as
  running a check without opening the file. Corrected in place rather than deleted,
  so what each check found sits where the wrong reason used to. **Treat every
  remaining *owed* cell's stated ground as unverified**: the verdict *owed* is
  reliable, the reason beside it is not.
- **The composite-shape check's yield splits, and the split is what to expect
  elsewhere.** Most entries were already decided by a published directive and simply
  never stated as a shape — cheap to write, and they close the silence the check is
  about. A minority were decided by nothing, and those are where the work is: one
  became a ban with grounds and a re-open condition, one is marked *permitted with
  conditions, and the conditions are unmeasured* because honest indecision beats an
  authored verdict, and **three turned out to belong to skills that already own
  them** — found by opening those files, not by remembering what they say.
